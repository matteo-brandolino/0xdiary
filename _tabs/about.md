**0xdiary** is a personal log of learning web security from scratch — DVWA, HackTheBox, CTFs, the occasional bug bounty concept. It's not a tutorial site. It's closer to a diary: what actually happened, including the mistakes, the dead ends, and the moments where an error message was telling me exactly what was wrong and I still didn't read it right for twenty minutes.

The assumption behind every post is that the honest mess is more useful than a clean walkthrough where everything works on the first try. If you've ever spent forty minutes debugging something that turned out to be a typo — welcome, you're among friends.

## How these posts are written

Here's the workflow, in full transparency:

1. I open a lab, break something, fix it, break it differently, eventually make it work
2. While this is happening I narrate everything to an AI — the attempts, the errors, the "wait why does this return a 404", the moment it clicks
3. The AI (Claude) takes that stream of consciousness and turns it into a readable post
4. I review it, make sure it sounds like me and not like a textbook, and publish

The technical content is mine — including all the mistakes, which I produce with impressive consistency. The prose is collaborative. I think this is worth saying openly because it's an increasingly normal way to write, and there's something slightly absurd about pretending otherwise.

Also, frankly, if I had to write proper prose after two hours of staring at SQL errors, nothing would ever get published.

## Disclaimer

All techniques documented here were performed on isolated lab environments. Running these attacks against systems you don't own or have written authorization to test is illegal in most jurisdictions.
